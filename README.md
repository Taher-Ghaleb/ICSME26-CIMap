# CIMap

**CIMap:** A Dataset of Cross-Platform CI/CD to GitHub Actions Mappings, extracted from the [GitHub Actions Importer](https://github.com/github/gh-actions-importer) documentation.

This repository is self-contained: source documentation (`docs/`), released artifacts (`data/`), build scripts (`scripts/`), and schema (`schema.sql`).

## Package layout

```
├── README.md
├── config.yaml              # Paths (relative to this repository root)
├── schema.sql               # SQLite DDL + views
├── requirements.txt
├── build.sh                 # Full rebuild from docs/
├── docs/                    # Documentation source (431 Markdown pages)
├── data/                    # Released and intermediate artifacts
├── scripts/                 # Extraction, validation, repair, SQLite load
├── lint/                    # yamllint config for doc fragments
├── tools/actionlint/        # Bundled actionlint (optional; auto-download supported)
└── tests/test_cimap_scripts.py  # Script and artifact tests (pytest)
```

Released data lives under **`data/`** (JSON and SQLite).

## Released artifacts (use these)

| File | Description |
|------|-------------|
| **`data/cimap_docs.json`** | Canonical JSON export (431 pages, 543 examples, validation metadata) |
| **`data/cimap_docs.sqlite`** | SQLite mirror of the same build (for SQL exploration) |
| **`data/stats.json`** | Summary counts (regenerated by `build_database.py`) |

## JSON and SQLite naming

The canonical JSON and the database describe the same corpus; table names differ from JSON keys on purpose.

| JSON (`cimap_docs.json`) | SQLite (`cimap_docs.sqlite`) |
|--------------------------|------------------------------|
| `pages[]` | `doc_pages` |
| `pages[].examples[]` | `doc_examples` |
| `examples[].input` | `doc_inputs` (0 or 1 row per example) |
| `examples[].output` | `doc_outputs` (0 or 1 row per example) |
| `examples[].validation` | columns on `doc_inputs` / `doc_outputs` |
| `input.execution_payloads` | `doc_inputs.execution_payloads_json` (JSON text, not normalized rows) |
| `validation_run` (corpus-level) | `dataset_builds.validation_run_json` |

`dataset_builds` stores build metadata only and is **not** linked by foreign keys to the documentation tables.

## Quality metrics

| Metric | Meaning | Released count |
|--------|---------|---------------:|
| **Complete pair** | Both `input` and `output` present (`has_pair` in `v_doc_examples_full`) | 520 |
| **Parse-ok pair** | Both sides pass parse checks (`parse_ok_pair`; `both_parse_ok` in `repair_comparison.json`) | 497 |
| **Output lint-ok pair** | Complete pair whose GitHub Actions output passes actionlint (`output_lint_ok = 1`) | 236 |
| **Syntactically clean pair** | Parse-ok on **both** sides **and** output lint-ok (strictest tier for ML export) | 230 |

`output_lint_ok_pairs` (236) − `syntactically_clean_pairs` (230) = 6 complete pairs where the output passes actionlint but the source input does not parse.

**actionlint** must be on `PATH` for output lint (recommended: `brew install actionlint`). Then:

```bash
python3 scripts/repair_docs.py --no-download
python3 scripts/build_database.py --fresh
```

Platforms: Jenkins, Azure DevOps, CircleCI, Travis CI, Bamboo, Bitbucket Pipelines, GitLab CI.

## Pipeline intermediates (optional)

These files support traceability and full reproduction; they are not required if you only consume the canonical release.

| File | Description |
|------|-------------|
| `data/docs_extracted.json` | Verbatim extraction from `docs/` |
| `data/docs_validated.json` | Extraction + parse/lint validation |
| `data/docs_repaired.json` | Parse-gated syntactic repairs (`content_original` preserved) |
| `data/docs_repaired_validated.json` | Repaired dataset + validation |
| `data/repair_comparison.json` | Before/after parse statistics from the repair pass (`both_parse_ok` = 497 after repair) |

## Quick start — JSON

```bash
python3 -c "import json; d=json.load(open('data/cimap_docs.json')); print(d['page_count'], 'pages', sum(len(p['examples']) for p in d['pages']), 'examples')"
```

## Quick start — SQLite

The released database is **`data/cimap_docs.sqlite`** (included in the repository).

```bash
sqlite3 data/cimap_docs.sqlite "SELECT COUNT(*) FROM doc_examples;"
sqlite3 data/cimap_docs.sqlite "SELECT platform, complete_pairs, parse_ok_pairs FROM v_quality_by_platform;"
```

Useful views (see `schema.sql`):

- `v_doc_examples_full` — one row per example with `has_pair`, `parse_ok_pair`, `syntactically_clean_pair`
- `v_ml_pairs` — **complete pairs only** (requires both input and output; no parse filter)
- `v_quality_by_platform` — per-platform counts aggregated from `v_doc_examples_full`

To regenerate the database and `stats.json` from the canonical JSON:

```bash
pip install -r requirements.txt
python scripts/build_database.py --fresh
# writes data/cimap_docs.sqlite and data/stats.json (paths in config.yaml)
```

## Full rebuild from source documentation

Requires Python 3.10+, the included `docs/` tree, `yamllint` (from `requirements.txt`), and **actionlint** on `PATH` (recommended: `brew install actionlint`) for output linting.

```bash
pip install -r requirements.txt
./build.sh
```

`build.sh` runs, in order:

| Step | Command | Main outputs |
|------|---------|--------------|
| 1 | `parse_docs.py --force` | `data/docs_extracted.json` |
| 2 | `validate_docs.py` | `data/docs_validated.json` |
| 3 | `repair_docs.py` | `data/docs_repaired.json`, `data/docs_repaired_validated.json`, **`data/cimap_docs.json`**, `data/repair_comparison.json` |
| 4 | `build_database.py --fresh` | **`data/cimap_docs.sqlite`**, **`data/stats.json`** |

Or run the same commands manually:

```bash
python scripts/parse_docs.py --force
python scripts/validate_docs.py
python scripts/repair_docs.py
python scripts/build_database.py --fresh
```

**Validation options**

- `validate_docs.py --skip-external` — parse checks only (faster; `syntactically_clean_pairs` will be 0)
- `validate_docs.py --no-download` — use actionlint from `PATH` (use after `brew install actionlint`)

## Configuration

`config.yaml` lists paths relative to **this repository root**:

- `docs_path` — documentation source (`docs/`)
- `cimap_docs_json`, `sqlite_path`, `stats_json` — canonical release under `data/`
- Other keys — pipeline intermediate JSON paths
